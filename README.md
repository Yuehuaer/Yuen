## 三、版本管理规范（全靠心情版）
### 1. 分支命名规则
- `main`：主分支（稳定版=跑起来不会立刻崩）
- `dev-moyu`：摸鱼开发分支（上班偷偷写的，可能藏着摸鱼网站链接）
- `feat-xxx`：功能分支（比如“feat-zhuanqian”赚钱小工具）
- `fix-xxx`：修bug分支（比如“fix-bengkui”修复一运行就崩溃的问题）
- `test-xxx`：测试分支（比如“test-new-version”测试新环境能不能用）

### 2. 提交信息规范（主打一个实话实说）
- 格式：`[类型] 一句话说明（别啰嗦）`
- 类型说明：
  - `feat`：新增功能（比如“[feat] 新增自动摸鱼提醒”）
  - `fix`：修bug（比如“[fix] 修复代码跑着跑着消失的bug”）
  - `docs`：更新文档（比如“[docs] 补充踩坑记录之‘中文符号杀我’”）
  - `refactor`：重构代码（比如“[refactor] 把杂乱代码改成稍微整齐的版本”）
  - `style`：格式调整（比如“[style] 给代码加空格，假装很专业”）
  - `test`：测试相关（比如“[test] 测试代码在摸鱼时能不能正常运行”）
  - `chore`：杂活（比如“[chore] 清理三年前的无用文件”）
