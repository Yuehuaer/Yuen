## 三、版本管理规范（全靠自觉版）
### 1. 分支命名规则
- `main`：主分支（稳定版=能跑不报错）
- `dev-fish`：摸鱼开发分支（上班偷偷写的代码）
- `feat-xxx`：功能分支（比如“feat-caipiao-generator”彩票号码生成器）
- `fix-xxx`：修bug分支（比如“fix-no-response”修复代码跑不动的bug）
- `test-xxx`：测试分支（比如“test-py311”测试新Python版本能不能用）

### 2. 提交信息规范（主打一个直白）
- 格式：`[类型] 一句话说明（别废话）`
- 类型说明：
  - `feat`：新增功能（比如“[feat] 新增摸鱼时长统计”）
  - `fix`：修bug（比如“[fix] 修复代码跑着跑着崩了的问题”）
  - `docs`：更新文档（比如“[docs] 补充踩坑日记之‘空格杀我’”）
  - `refactor`：重构代码（比如“[refactor] 把屎山代码整理成稍微能看的屎山”）
  - `style`：格式调整（比如“[style] 给代码加空格，假装很规范”）
  - `test`：测试相关（比如“[test] 测试代码能不能在摸鱼时正常运行”）
  - `chore`：杂活（比如“[chore] 清理没用的垃圾文件”）
